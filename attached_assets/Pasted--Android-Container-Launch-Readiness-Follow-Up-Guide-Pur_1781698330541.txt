> **Purpose.** This is a follow‑up verification guide for the BabelWords Android app,
> which ships as a **native WebView container** wrapping this web app. Use it to confirm
> that **every element works inside the Android container — especially all paid features —
> before publishing to the Google Play Store.** The final section directs a **full architect

>

> or has an explicit, written waiver. Items marked **�blocker** must be resolved.

---

## 0. How the container is wired (read first)

The Android app does **not** reimplement gameplay. It loads the same web app inside a
`WebView` and bridges to native code for the things a browser can't do: billing, ads,
microphone, and lifecycle.

| Concern | Web side | Native side (Android) |
|---|---|---|
| Platform detection | `client/src/lib/nativeBridge.ts` → `detectPlatform()` (looks for `window.AndroidSubscriptionBridge`) | `SubscriptionBridge.kt` injects `AndroidSubscriptionBridge` via `@JavascriptInterface` |
| In‑app purchases | `client/src/lib/nativeBridge.ts`, `client/src/pages/store.tsx` | `SubscriptionBridge.kt`, `SubscriptionManager.kt` (Play Billing) |
| Purchase verification | `POST /api/iap/google/verify` in `server/routes.ts` | — |
| Ads | `public/adbridge.js`, `client/src/lib/adController.ts` | `AdBridge.kt` / `AdMobManager.kt` (see `docs/AdMobBridge.kt`) |
| Voice / mic / audio | `client/src/lib/audioContext.ts`, `/ws/stt`, `/api/tts`, `/api/guardian-tts` | `ConversationWebViewManager.kt` (mic permission + autoplay) |
| Lifecycle / network | `subscription_event` + custom window events | `ConversationWebViewManager.kt` |

**Bridge direction:**
- **Web → Native:** the web app calls methods on the injected object, e.g.
  `window.AndroidSubscriptionBridge.purchaseProduct(productId, type)`.
- **Native → Web:** the native layer dispatches a DOM event the web app listens for:
  `window.dispatchEvent(new CustomEvent('subscription_event', { detail: {...} }))`.

Reference docs already in this repo: `docs/android-integration-guide.md`,
`docs/ANDROID_WEBVIEW_CALLBACKS_GUIDE.md`, `docs/ADMOB_ANDROID_INTEGRATION.md`,
`docs/ANDROID_CONVERSATION_MODE_GUIDE.md`.

### 3.2 Bridge contract (client ⇄ native)

**Web → Native** (called from `nativePurchase()` / `nativeRestore()`):
- `AndroidSubscriptionBridge.purchaseProduct(androidProductId, type)` — `type` is `'inapp'` or `'subs'`.
- `AndroidSubscriptionBridge.subscribe(androidProductId)` — legacy subscription path.
- `AndroidSubscriptionBridge.restorePurchases()`.

**Native → Web** (dispatched as `subscription_event`, `detail.event` is one of):
- `product_purchased` / `subscription_purchased` → `detail` must include `productId`, and for verification `purchaseToken` (and optionally `transactionId`).
- `product_restored` / `subscription_restored`.
- `purchase_error` / `subscription_error` → include `message` (and `productId` if known).

☐ Native sends the **exact** `event` strings above (typos here silently break the purchase resolve).
☐ `purchaseToken` is included on success — the server needs it to verify (see 3.3).
☐ User‑cancel results in a clean error/cancel event (no spinner hang). The web side has a 5‑min safety timeout in `nativeBridge.ts`, but native should respond immediately.

### 3.3 Server verification & crediting

After a successful native purchase the client should hand the token to the server, which verifies and credits the account.

- Endpoint: `POST /api/iap/google/verify` (`server/routes.ts`).
- Body: `{ purchaseToken, productId, packageName }` (default package `com.linguawonder.app`).
- Verification: when `GOOGLE_PLAY_KEY` is set, the server uses the `googleapis`
  `androidpublisher` v3 API — `purchases.subscriptions.get` for subs, `purchases.products.get`
  for consumables — then credits `hintBalance` for hint packs.
- Related endpoints: `GET /api/iap/balance`, `POST /api/iap/restore`,
  `POST /api/iap/test-purchase` (dev only — see 3.6).

> ### 🚨🚧 BLOCKER — server‑side Google verification cannot run today
> `server/routes.ts` calls `const { google } = await import('googleapis')`, **but the
> `googleapis` package is not installed** in this project (it does not resolve at runtime).
> Consequences:
> - If `GOOGLE_PLAY_KEY` **is set**, the dynamic import will **throw** when a real Android
>   purchase is verified — purchases will not be securely credited.
> - If `GOOGLE_PLAY_KEY` is **not set**, the server **skips verification and credits hints
>   on trust** — acceptable for internal testing only, **not** for production (anyone can
>   forge a purchase call).
>
> **Before publishing you must:**
> ☐ Install `googleapis` (via the package manager — do **not** hand‑edit `package.json`).
> ☐ Set the `GOOGLE_PLAY_KEY` secret to the Play service‑account JSON (use the secrets flow; never commit it).
> ☐ Grant that service account the "View financial data / Manage orders" permission in Play Console.
> ☐ Re‑run a real sandbox purchase and confirm `/api/iap/google/verify` returns success and `hintBalance` increases.

☐ `GOOGLE_PLAY_KEY` configured in **production** secrets (not just dev).
☐ `hintBalance` increases by the correct amount per product after verify.
☐ Verification **rejects** an invalid/forged `purchaseToken`.
☐ Double‑submitting the same token does not double‑credit (idempotency / token reuse handling).

☐ All 3 store tabs render in the container: **Boosters**, **Cosmetics**, **Premium**.
☐ Prices, names, and the platform label show **"Google Play"** (`platformLabel()` returns it on Android).

### 3.5 Per‑product test matrix (run each on a real device w/ a Play license tester)

For **each** of the 7 products:
☐ Tap → native Google sheet opens → complete purchase → entitlement granted in‑app.
☐ Consumables: balance increases and the item is re‑purchasable afterward.
☐ Subscriptions: perks activate (Scholar XP boost / Premium cosmetics + monthly hints).
☐ Cancel mid‑purchase → no entitlement, clean UI, can retry.
☐ Kill the app right after pay, relaunch → entitlement still granted (resolved via verify/restore).

### 3.6 Restore & edge cases

☐ **Restore purchases** re‑grants active subscriptions on a fresh install / new device.
☐ Subscription **renewal** keeps perks active; **expiry/cancel** removes them.
☐ Refund / revoke removes the entitlement on next verify.
☐ Offline at purchase time → graceful error, retried when back online.
☐ `POST /api/iap/test-purchase` is **disabled or guarded** in production builds (it must not let users self‑grant).
