Android's network security config lets you control which domains your app can communicate with and how. Production builds sometimes lock this down in ways that accidentally block ad traffic.
Where it's configured
android/app/src/main/res/xml/network_security_config.xml
Referenced in your manifest:
xml<application
    android:networkSecurityConfig="@xml/network_security_config"
    ...>
Common problematic configurations
Blocking cleartext (HTTP) traffic too aggressively:
xml<network-security-config>
    <base-config cleartextTrafficPermitted="false" />
</network-security-config>
Some ad networks still use HTTP for certain requests, tracking pixels, or redirects. Blocking all cleartext can break ad loading silently.
Domain whitelisting that's too narrow
xml<network-security-config>
    <domain-config cleartextTrafficPermitted="true">
        <domain includeSubdomains="true">yourdomain.com</domain>
    </domain-config>
    <base-config cleartextTrafficPermitted="false" />
</network-security-config>
This only allows traffic to your domain, blocking everything else including Google's ad servers.
What Google ads need to reach
AdMob communicates with dozens of domains: googleads.g.doubleclick.net, pagead2.googlesyndication.com, tpc.googlesyndication.com, and many others. Plus any mediation partners you're using.
Safe configuration for ads
xml<network-security-config>
    <base-config cleartextTrafficPermitted="true">
        <trust-anchors>
            <certificates src="system" />
        </trust-anchors>
    </base-config>
</network-security-config>
Or if you want to be more restrictive while still allowing ads:
xml<network-security-config>
    <base-config cleartextTrafficPermitted="false" />
    <domain-config cleartextTrafficPermitted="true">
        <domain includeSubdomains="true">doubleclick.net</domain>
        <domain includeSubdomains="true">googlesyndication.com</domain>
        <domain includeSubdomains="true">googleadservices.com</domain>
        <domain includeSubdomains="true">google.com</domain>
        <domain includeSubdomains="true">googleapis.com</domain>
        <domain includeSubdomains="true">gstatic.com</domain>
    </domain-config>
</network-security-config>
How to diagnose
Run your release build and watch logcat filtered for network errors:
bashadb logcat | grep -i "cleartext\|network\|ssl\|http"
You'll see messages like Cleartext HTTP traffic not permitted if this is blocking your ads.
Debug vs release difference
Android Studio often sets debuggable true for debug builds, which relaxes some network security enforcement. Release builds enforce it strictly, which explains why BrowserStack (likely running debug) works while production doesn't.
