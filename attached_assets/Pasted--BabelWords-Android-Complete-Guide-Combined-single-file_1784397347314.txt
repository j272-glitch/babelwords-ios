## 1. Prerequisites & Toolchain

| Component | Version | Notes |
|---|---|---|
| Android Gradle Plugin (AGP) | **8.5.1** | Higher versions have historically caused manifest corruption in CI. |
| Gradle | **8.9** | `android/gradle/wrapper/gradle-wrapper.properties` |
| Kotlin | **2.2.0** | Required by play-services-ads 24.x (see §1.1). |
| JDK | **17** | Required for Gradle 8.x. |
| compileSdk / targetSdk | **35** | Don't raise to 36 unless you also move the ads SDK to 25.x. |
| minSdk | **24** | |
| build-tools | **35.0.0** | |
| play-services-ads | **24.9.0** | Core AdMob SDK. |

All toolchain versions live in **`android/build.gradle`** (plugins + ext block). `android/app/build.gradle` inherits them via `rootProject.ext.*`.

### 1.1 ⚠️ play-services-ads ↔ Kotlin version coupling (critical trap)

- **play-services-ads 24.x is compiled with Kotlin 2.x.** The 24.9.0 jars carry Kotlin **metadata 2.2.0** and transitively pull **kotlin-stdlib 2.1.0**.
- A **Kotlin 1.9.x** compiler can only read metadata up to 2.0.0, so the build fails at `:app:compileReleaseKotlin` with cascading errors (e.g. `Unresolved reference: mapOf`) — those are *symptoms* of the compiler failing to load stdlib, not real code bugs.

**Rule:** the project's Kotlin version must be **>=** the Kotlin version the ads SDK was built with. Use **Kotlin 2.2.0** to match play-services-ads 24.9.0.

**compileSdk ceiling:** stay on the **24.x** ads line while `compileSdk = 35`. The **25.x** line targets Android 16 / API 36 and can force `compileSdk 36`.

## 2. Version Bumping (every release)

Change the version in **two places** — Gradle files and the primary CI workflow. The CI build overrides Gradle defaults with `-Pandroid.injected.version.code/name`, so workflow inputs/env take precedence. Keep them synchronized or CI will ship a stale/duplicate number.

1. **Gradle files** (the fallbacks when CI inputs are absent):
   - `android/app/build.gradle` → `versionCode` and `versionName`
   - `android/build.gradle` → the `versionCode` / `versionName` in the `subprojects { ... defaultConfig { ... } }` block
2. **CI workflow** (`.github/workflows/android-sdk-update-v25.yml`) → three spots:
   - the `version_name` input **description**
   - the `version_name` input **default**
   - the `env:` fallbacks `VERSION_CODE` and `VERSION_NAME`

**Precedence rule:** `workflow_dispatch` input → env fallback → Gradle default.

**Rules**
- `versionCode` must be a **higher integer** than any artifact ever uploaded to Play (across ALL tracks). Play rejects re-used or lower codes.
- A version number, once used in a build, is "burned" — bump again for the next attempt even if the previous build failed and produced nothing.
- After editing, verify there are no stragglers:
  ```bash
  rg --color never -n "<OLD_VERSION>" android/ .github/workflows/android-sdk-update-v25.yml
  ```

## 3. v50 — App Open Ads, ANR Prevention, Lifecycle Guards, Mic Safety

### 3.1 What v50 Adds (vs the Pre-v50 Interstitial-Only Setup)

| Feature | Pre-v50 | v50 | Revenue Impact |
|---------|---------|-----|----------------|
| Interstitial | Static image only | Same | Baseline |
| Rewarded | Removed (alias to interstitial) | Same alias | No change |
| App Open | None / foreground interstitial alias | Real AppOpenAd with warm-resume | **+12–17 impressions/day** |
| ANR prevention | None | `OPTIMIZE_INITIALIZATION` + `OPTIMIZE_AD_LOADING` | Fewer crashes = more impressions |
| Lifecycle guards | Basic | `isDestroyed` flag on all ad managers | No leaked Activities or stray callbacks |
| Mic safety | None | JS heartbeat + 45s watchdog | No blocked ads during recording |
| Speed-aware preload | Always preload | Skip on slow cellular | Better UX on 2G/3G |
| Frequency cap | In-memory only | SharedPreferences (survives process death) | Consistent 4h cap |

### 3.5 AppOpenAdManager.kt — The New File

Create at `android/app/src/main/java/«BW_PACKAGE»/ads/AppOpenAdManager.kt`.

**Key behaviors to preserve:**

| Behavior | How it works |
|----------|--------------|
| **Warm-resume** | `onStop` records timestamp; `onResume` checks if ≥5s passed → shows ad |
| **4h frequency cap** | Reads/writes `SharedPreferences` key `app_open_last_show_ms` |
| **15s timeout** | `handler.postDelayed` with `LOAD_TIMEOUT_MS` → nulls stale ad |
| **Error backoff** | No-fill → 60s, timeout → 20s, network → 15s |
| **Destroyed guard** | Every `loadAd()`, `showAd()`, and callback body checks `if (isDestroyed) return` |
| **Thread confinement** | All SDK callbacks are wrapped in `handler.post {}` so they run on the main Looper, serialized with `cleanup()` |

**Lifecycle wiring in MainActivity.kt:**

```kotlin
class MainActivity : AppCompatActivity() {
    private lateinit var appOpenAdManager: AppOpenAdManager

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        // ... existing setup ...
        appOpenAdManager = AppOpenAdManager(this)
        ProcessLifecycleOwner.get().lifecycle.addObserver(appOpenAdManager)
    }

    override fun onDestroy() {
        super.onDestroy()
        appOpenAdManager.cleanup()
    }
}
```

### 3.8 Mic Safety (if BabelWords has speech/audio features)

**Add the flag and watchdog in MainActivity.kt:**

```kotlin
@Volatile
var isMicActive: Boolean = false  // Do NOT assign directly — use setMicState()

private val micWatchdogHandler = Handler(Looper.getMainLooper())
private var micWatchdogRunnable: Runnable? = null
private const val MIC_WATCHDOG_MS = 45_000L

fun setMicState(active: Boolean) {
    isMicActive = active
    if (active) {
        micWatchdogRunnable?.let { micWatchdogHandler.removeCallbacks(it) }
        val watchdog = Runnable {
            if (isMicActive) {
                isMicActive = false
                Log.w("MicWatchdog", "isMicActive reset after ${MIC_WATCHDOG_MS / 1000}s (stale lock cleared)")
            }
        }
        micWatchdogRunnable = watchdog
        micWatchdogHandler.postDelayed(watchdog, MIC_WATCHDOG_MS)
    } else {
        micWatchdogRunnable?.let {
            micWatchdogHandler.removeCallbacks(it)
            micWatchdogRunnable = null
        }
    }
}
```

> **Critical:** Name the method `setMicState`, NOT `setMicActive`, or you'll get a "platform declaration clash" build error (Kotlin auto-generates a setter for the `var`).

**JS heartbeat:** While any audio track is `live`, re-call `window.AndroidBridge.notifyMicActive(true)` every 15 seconds. Each call routes through `setMicState(true)`, which re-arms the 45s watchdog.

**Block App Open ad during recording:** In `AppOpenAdManager.showAdIfAvailable()`:

```kotlin
if (activity.isMicActive) {
    Log.d("AppOpen", "Blocked — mic is active")
    return
}
```

### 3.9 Audio Routing Symmetry

Ads need `AudioManager.MODE_NORMAL` while on screen. Toggle audio mode on every show/dismiss/fail edge:

```kotlin
private fun setAudioModeForAd() {
```

## 4. v53 — Unified Interstitial Pipeline

### 4.1 What v53.1 Changes (vs v50/v51 Dual-Pipeline Setup)

| Area | Pre-v53.1 (v50/v51) | v53.1 | Why |
|------|----------------------|-------|-----|
| Interstitial load ownership | **Two independent pipelines** — `AdPreloadManager` and `AdMobBridge` each call `InterstitialAd.load()` with separate `isInterstitialLoading` flags | **One pipeline** — `InterstitialAdManager` owns all load/show state | Prevents duplicate `InterstitialAd.load()` calls on cold start / Test Lab |
| `isInterstitialReady()` bridge poll | Checked only bridge-local state; never consulted `AdPreloadManager` cache | Checks `InterstitialAdManager.isReady() ‖‖ AdPreloadManager.isInterstitialReady()` | Web app "ad ready" polls were wrong when preload had a cached ad |
| Load throttle (`lastLoadTime`) | Stamped on every `load()` call, even pre-resume cold-start loads | Only advances when `isActivityResumed=true` | Pre-resume loads no longer consume throttle budget |
| `isLoading` guard | `@Volatile Boolean` (not actually atomic) | `AtomicBoolean` with `compareAndSet(false, true)` | Race-safe single-flight guard |
| `show()` -> stale/missing ad | Called `load()` but **did not** set `pendingShow`; show request was dropped | Sets `pendingShow=true` before `load()`; `onAdLoaded` auto-shows | Test Lab / user show-on-cold-start now works |
| Network callback | Existed but **never registered** | Registered in `AdMobBridge.init()` | Auto-reload when connectivity returns after offline period |

### 4.2 New File: InterstitialAdManager.kt

Create at `android/app/src/main/java/«BW_PACKAGE»/ads/InterstitialAdManager.kt`.

This is a **new class** (not a rename). It replaces the interstitial portions of both `AdPreloadManager` and `AdMobBridge`. Copy LinguaVibe's `InterstitialAdManager.kt` **verbatim** (it is domain/ad-unit agnostic — those are constructor parameters). The file is ~770 lines and contains:

- **Constants:** expiry (45 min), refresh-before-expiry (40 min), load timeout (15s), retry backoff (5–60s), frequency cap (30s), load throttle (30s)
- **State:** `AtomicBoolean isLoading`, `@Volatile isShowingAd`, `interstitialAd`, `loadTime`, `lastLoadTime`, `lastShowTime`
- **Session token:** `AtomicLong sessionId` for stale-callback safety (destroy increments it, callbacks check it)
- **Lifecycle:** `LifecycleEventObserver` with `ON_START` auto-reload if stale
- **Network callback:** `registerNetworkCallback()` / `unregisterNetworkCallback()` for auto-reload on connectivity return
- **Public API:** `load()`, `show(activity)`, `isReady()`, `isCurrentlyShowingAd`, `setActivityResumed(Boolean)`, `setActivity(Activity)`, `registerNetworkCallback()`, `unregisterNetworkCallback()`, `destroy()`
- **Callbacks:** `onEvent`, `onAdPresented`, `onAdDismissed`, `subscriptionChecker`
- **Telemetry:** `emit(type, subtype, code, error)` — fires `onEvent` callback for bridge/web consumption

### 4.3 The 3 v53.1.1 Architect-Review Fixes

If copying from a **pre-v53.1.1** snapshot, apply these 3 patches:

**Fix 1: `pendingShow` in `show()` for stale/missing ad**

In `show()`, both the "ad stale" and "no cached ad" branches must set `pendingShow = true` before calling `load()`:

```kotlin
// Staleness guard
if (!isFresh()) {
    log("Ad stale — reloading with auto-show", "W")
    emit("showSuppressed", code = -15, error = "ad_stale_reloading")
    emit("loading")
    pendingShow = true   // ← ADD THIS
    load(activity)
    return false
}

val ad = interstitialAd ?: run {
    log("No cached ad — triggering load", "W")
    emit("showSuppressed", code = -16, error = "no_cached_ad")
    emit("loading")
    pendingShow = true   // ← ADD THIS
    load(activity)
    return false
}
```

**Fix 2: `registerNetworkCallback()` wiring**

In `AdMobBridge.init()`, add after manager creation:

```kotlin
interstitialManager = InterstitialAdManager(activity, currentInterstitialId)
// ... set callbacks, wire to AdPreloadManager ...
interstitialManager?.registerNetworkCallback()   // ← ADD THIS
ProcessLifecycleOwner.get().lifecycle.addObserver(interstitialManager!!)
```

**Fix 3: `isLoading` as `AtomicBoolean` with CAS**

Change field declaration:

```kotlin
// BEFORE (volatile boolean, not actually atomic)
@Volatile
private var isLoading = false

// AFTER (true CAS guard)
private val isLoading = AtomicBoolean(false)
```

Change the guard:
```kotlin
if (!isLoading.compareAndSet(false, true)) {
    log("Already loading — skipping duplicate request")
    return
}
```

### 4.4 Modify AdPreloadManager.kt — Delegate Bridge

The interstitial-specific load/show/ready/retry code in `AdPreloadManager` is now a **delegate** to `InterstitialAdManager`. Do not delete `AdPreloadManager` — it still handles SDK init, UMP consent, rewarded preloading, and the Test Lab auto-show wiring.

**Add the delegate bridge:**

```kotlin
// v53.1: Delegate bridge to unified InterstitialAdManager
private var interstitialManagerRef: WeakReference<InterstitialAdManager>? = null

fun setInterstitialManager(manager: InterstitialAdManager?) {
    interstitialManagerRef = manager?.let { WeakReference(it) }
    log("InterstitialAdManager ref ${if (manager == null) "cleared" else "set"}")
}

private fun getInterstitialManager(): InterstitialAdManager? =
    interstitialManagerRef?.get()?.takeIf { !it.isCurrentlyShowingAd }
```

**Delegate interstitial methods:**

```kotlin
fun preloadInterstitial(context: Context, requiredSession: Long = -1L) {
    getInterstitialManager()?.let { mgr ->
        log("Delegating preloadInterstitial to InterstitialAdManager")
        mgr.load()
        return
    }
    // ... existing fallback logic stays ...
}

fun isInterstitialReady(): Boolean {
    getInterstitialManager()?.let { return it.isReady() }
    return isInterstitialFresh()
}

fun showInterstitial(activity: Activity): Boolean {
    getInterstitialManager()?.let { mgr ->
        log("Delegating showInterstitial to InterstitialAdManager")
        val shown = mgr.show(activity)
        return shown
    }
    // ... existing fallback logic stays ...
}
```

**Keep the Test Lab callback wiring.** Do not change `onInterstitialReady`, `onAdImpression`, `onAdShown`, `onAdDismissed`. The `AdMobBridge` forwards manager events back into these callbacks, so `MainActivity`'s Test Lab auto-show still works unchanged.

### 4.5 Modify AdMobBridge.kt — Remove Interstitial State

**Delete from AdMobBridge:**
- `interstitialAd: InterstitialAd?`
- `isInterstitialReady: Boolean`
- `isInterstitialLoading: Boolean` / `interstitialIsLoadingAtomic: AtomicBoolean`
- `interstitialLoadTime`, `interstitialRetryDelay`, `interstitialRetryCount`
- `interstitialRetryRunnable`, `interstitialRefreshRunnable`, `showWatchdogRunnable`
- `interstitialImpressionFired`, `lastInterstitialLoadTime`
- `pendingShowInterstitial`
- `loadInterstitialAd()` method
- Interstitial-specific `FullScreenContentCallback`
- Interstitial-specific retry/refresh/watchdog scheduling

> **Keep:** The JS-exposed methods `loadInterstitialAndShow()`, `showInterstitial()`, `preloadInterstitial()`, `isInterstitialReady()`, `isInterstitialLoaded()`, plus all telemetry formatting (`notifyAdEvent`, `notifyJs`), banner handling, consent, and recovery.

**Add `interstitialManager` field and init wiring:**

```kotlin
// v53.1: Unified interstitial manager (replaces bridge-local interstitial state)
internal var interstitialManager: InterstitialAdManager? = null

init {
    interstitialManager = InterstitialAdManager(activity, currentInterstitialId)
    interstitialManager?.setActivity(activity)
    interstitialManager?.onAdPresented = { notifyAdPresented() }
    interstitialManager?.onAdDismissed = { notifyAdDismissed() }

    interstitialManager?.let { mgr ->
        AdPreloadManager.setInterstitialManager(mgr)
        mgr.onEvent = { type, subtype, code, error ->
            if (type == "interstitial") {
                when (subtype) {
                    "ready"      -> AdPreloadManager.onInterstitialReady?.invoke()
                    "impression" -> AdPreloadManager.onAdImpression?.invoke("interstitial")
                    "loaded"     -> AdPreloadManager.onInterstitialReady?.invoke()
                }
            }
            if (subtype == "impression") {
                totalImpressions++
                interstitialImpressions++
            }
            notifyAdEvent(type, subtype, code, error)
        }
    }

    interstitialManager?.registerNetworkCallback()
    ProcessLifecycleOwner.get().lifecycle.addObserver(interstitialManager!!)
}
```

**Delegate JS interstitial methods to manager:**

```kotlin
@JavascriptInterface
fun loadInterstitialAndShow() {
    log("JS → loadInterstitialAndShow()")
    mainHandler.post {
        val mgr = interstitialManager ?: return@post
        mgr.autoShow = true
        mgr.load()
    }
}

@JavascriptInterface
fun showInterstitial() {
    log("JS → showInterstitial()")
    mainHandler.post {
        val mgr = interstitialManager ?: return@post
        val act = activityRef.get() ?: return@post
        mgr.show(act)
    }
}

@JavascriptInterface
fun preloadInterstitial() {
    log("JS → preloadInterstitial() [preload only]")
    mainHandler.post {
        interstitialManager?.load()
    }
}

@JavascriptInterface
fun isInterstitialReady(): Boolean {
    return interstitialManager?.isReady()
        ?: AdPreloadManager.isInterstitialReady()
}

@JavascriptInterface
fun isInterstitialLoaded(): Boolean = isInterstitialReady()
```

## 5. v54 — Mediation (Unity + Vungle), Rewarded Telemetry, Test Lab Fixes

### 5.1 Unity Ads + Liftoff/Vungle Mediation

> **Critical: use BIDDING, not waterfall.** Google ended Unity Ads waterfall mediation on January 31, 2026. Waterfall groups for Unity no longer serve. Configure Unity as **bidding** in the AdMob dashboard.

**Step 1 — Match the adapter to your SDK**

The Unity mediation adapter version **must** match your Google Mobile Ads SDK. A mismatch makes Unity **silently fail to fill — no error in logs.**

This app is on **GMA SDK 24.9.0**, so use:

```gradle
dependencies {
    // Google Mobile Ads SDK (already present)
    implementation 'com.google.android.gms:play-services-ads:24.9.0'

    // Unity Ads mediation — adapter + SDK (versions must match GMA 24.9.0)
    implementation 'com.google.ads.mediation:unity:4.16.6.0'
    implementation 'com.unity3d.ads:unity-ads:4.16.6'
```

## 6. v55.1 — Show-Path Hardening

### 6.1 What v55.1 Fixes (10 critical show-path bugs)

| # | Bug | Impact | Fix |
|---|---|---|---|
| 1 | Frequency cap consumed at `show()` call, not at actual impression | Failed shows burned the cap, reducing real impressions by ~10-20% | Cap consumed only in `onAdShowedFullScreenContent`; failed shows do NOT burn cap |
| 2 | Aggressive retry policy on every failure | Inflated request count, hurting I/R ratio | Non-retryable errors (`not_resumed`, `already_showing`, `background`, `null_activity`) skip retry; only `ad_stale_reloading` and `no_cached_ad` auto-retry |
| 3 | App Open cold-start used blind 2s delay | If SDK not init'd by delay → no ad for entire session | Explicit state machine: `SDK_WAIT`(500ms) → `SHOW_WINDOW`(1200ms) → `SHOWN` or `SKIPPED` |
| 4 | `shouldPreload(false)` used `LOW_INTENT=0.15` | Inflates request denominator, hurting I/R | Changed to `MEDIUM_INTENT=0.35` for both cached and uncached preloads |
| 5 | No session-level impression budget | Interstitial + App Open + Rewarded could stack | Added 45s global cooldown across ALL formats; code `-20` |
| 6 | AppOpen pending show survived indefinitely | Stale show could fire on unrelated future load | 8s expiry on `pendingShow`; auto-cleared if load settles after deadline |
| 7 | Rewarded preload completely removed | 2-5s tap-to-show delay → user abandonment | Restored on WiFi only; negligible data cost, significant fill gain |
| 8 | `isShowingAd` stuck true after exception | Blocks ALL future shows with code `-4` | Try/catch + watchdog around `.show()`; auto-clear on stall or throw |
| 9 | No `showRequested` / `showSuppressed` telemetry | Web Promise hangs, "0 impressions" mystery | `showRequested` fires on entry; `showSuppressed` fires on every guard block with code + reason |
| 10 | Post-cleanup callbacks trigger reload | `clearCallbacks()` then SDK callback fires → unexpected load | `@Volatile isDestroyed` guard at top of every load entry point |

### 6.2 New Files (v55.1)

| File | Purpose |
|---|---|
| `AdIntentScorer.kt` | Scores user interaction intent (0.0–1.0). Warm-resume preloads gated by `MEDIUM_INTENT=0.35`. MainActivity `onStop` resets the scorer session. |
| `AdExperimentConfig.kt` | A/B frequency-cap bucketing by install ID. Buckets 34/33/33 into CONTROL (30s) / VARIANT_A (20s) / VARIANT_B (45s). SharedPreferences override for emergency rollback. |
| `InterstitialAdManager.kt` | Unified owner of interstitial load/show state. Delegated from `AdPreloadManager`. |
| `RewardedAdManager.kt` | Mirrors interstitial architecture for rewarded ads. Frequency cap, pending-show, telemetry, intent scorer, experiment config. |

### 6.3 Telemetry Funnel (v55.1)

Every ad show now produces a complete event sequence:

```
showRequested → [guards may emit showSuppressed(code, reason)] → showStarted → onAdShowed → onAdImpression → onAdDismissed
```

| Event | Emitted When | Formats |
|---|---|---|
| `showRequested` | Entry of `show()` | Interstitial, Rewarded, App Open |
| `showSuppressed` | Any guard blocks show (with code + reason) | All |
| `showStarted` | Right before calling `ad.show()` | Interstitial, Rewarded |
| `failedToShow` | Show threw or stalled past watchdog | All |

## 7. v56 — AdExperimentConfig Crash Fix, Compile-Check Removal

### 7.1 The Crash

`AdExperimentConfig.computeVariant()` crashed with `NumberFormatException: For input string: "97d62620"` because Kotlin's `toInt(16)` is a **signed** parse — any hex value above `0x7fffffff` overflows.

**Chain reaction:**
1. `AdMobBridge.<init>` constructs `AdExperimentConfig`
2. `computeVariant` throws on certain install IDs
3. `AdMobBridge` never registers with the WebView
4. Entire ad stack (preload, App Open, interstitial, rewarded) never initializes
5. Robo test produces **zero ad impressions**; CI fails

### 7.2 The Fix

```kotlin
// BEFORE (crashes on 97d62620, aaf51aba, ...)
val bucket = hash.take(8).toInt(16) % 100

// AFTER (v56)
val bucket = try {
    ((hash.take(8).toLong(16) and 0xffffffffL) % 100).toInt()
} catch (e: NumberFormatException) {
    0 // fallback to CONTROL
}
```

Also: `computeVariant` and `md5` changed from `private` to `internal` so the regression test can reach them.

### 7.3 Regression Test

`AdExperimentConfigTest` (androidTest) added to the CI Firebase Test Lab suite:

| Test | Validates |
|---|---|
| `computeVariant_highHexPrefix_doesNotThrow` | `97d62620` computes without exception |
| `computeVariant_secondHighHexPrefix_doesNotThrow` | `aaf51aba` computes without exception |
| `md5_returnsConsistentHash` | MD5 is deterministic and 32 chars |
| `computeVariant_producesValidBucket` | 100 random inputs all return valid variants |

### 7.4 Compile-Check Removal

The standalone `Kotlin Compile Check` workflow (`compile-check.yml`) and the internal compile-check step inside the main build workflow were both removed:
- `compile-check.yml`: auto-trigger on push/PR disabled; now `workflow_dispatch` only
- `android-sdk-update-v25.yml`: compile-check job and "Quick Compile Check" step removed
- Build goes straight to `bundleRelease`; real compile errors caught by Gradle itself

## 9. Firebase Test Lab Instrumentation Gates

The CI workflow runs **instrumentation tests on real cloud devices** as release gates. These are not optional — they hard-fail the build on `push` to `main` if logcat markers are missing or assertions fail.

| Test class | What it protects | CI hard-fail marker |
|---|---|---|
| `AudioFocusLossInstrumentedTest` | OS mic/audio focus revocation fast path | `MicWatchdog: audio focus lost` + `isMicActive reset` |
| `AppOpenAdManagerRotationTest` | Activity destroyed mid-rotation while ad callback in flight → no crash, no reload | `TestRunner: finished: .*AppOpenAdManagerRotationTest` |
| `MicResumeReconciliationTest` | `MIC_RESUME_RECONCILIATION_MS` ceiling ≤ 10 s; stale mic lock cleared within timeout | `TestRunner: finished: .*MicResumeReconciliationTest` |
| `AdPreloadManagerColdStartTest` | Race-guard invariants (no-inflight + interstitial + rewarded) on fresh process | `COLD_START_RACE_GUARD: all 3 invariants` + `NO_INFLIGHT_RACE_GUARD` |
| `AdMobBridgeShowTelemetryTest` | `showRequested` + `showSuppressed` telemetry deterministically emitted by guards | `TestRunner: finished: .*AdMobBridgeShowTelemetryTest` |
| `RewardedAdIntegrationTest` | Rewarded ad telemetry markers (v54) | `REWARDED_SHOW_ATTEMPT` + `REWARDED_SHOWN` + `REWARDED_EARNED` |
| `AdExperimentConfigTest` | `computeVariant` never throws on high hex prefixes (v56) | `TestRunner: finished: .*AdExperimentConfigTest` |

> **Note:** The `coldStart_onFreshProcess_firesPreloadAndDeliversReadyCallback()` test is `@Ignore` (requires real AdMob SDK + network; crashes on Test Lab emulators). CI only validates the **deterministic race-guard** subset — not full cold-start fill.
>
> **Ad serving verification (Robo test):** On `push` to `main`, zero ad impressions is a **hard fail** (safety gate). On `workflow_dispatch` / PR, zero impressions is a **warning only** — instrumentation tests already validate the code deterministically.

**Required secrets:** `GCP_SA_KEY` and `GCP_PROJECT_ID` must be present in GitHub Secrets for Test Lab runs. Without them, the build skips instrumentation gates on `workflow_dispatch` but **hard-fails on `push` to `main`**.

### 9.1 AndroidTest Host Activity Invariant

Instrumentation tests that need a real Activity instance use `TestHostActivity`:
- **Must extend `ComponentActivity`** (not plain `Activity`). ActivityScenario from `androidx.test:core` has intermittent launch failures on Firebase Test Lab emulators with plain `Activity` subclasses.
- **Must NOT extend `AppCompatActivity`**. A platform translucent theme (`@android:style/Theme.Translucent.NoTitleBar`) is used in `androidTest/AndroidManifest.xml` to avoid build-time resource resolution errors.
- **Must be `exported="true"`** in `androidTest/AndroidManifest.xml` (v54 fix).

```kotlin
class TestHostActivity : ComponentActivity()
```

### 9.2 Cold-Start Testing — Two-Stage CI Approach

You cannot simulate cold start (process death) inside a single instrumentation test because the test runner and target app share the **same process**. Calling `am force-stop` from within the test kills the instrumentation runner along with the app.

**The CI workaround:** Two separate `gcloud firebase test android run` invocations:
1. **Robo test** — exercises the app, then Test Lab kills the process
2. **Instrumentation test** — runs on a **fresh device** with JVM singleton fields at defaults

### 9.3 Same-Process Test Isolation — @BeforeClass Reset

When Test Lab runs multiple test classes, they may execute in the **same process**. AdPreloadManager is a JVM singleton; stale state from a prior test can silently corrupt assertions.

**Pattern:**
```kotlin
@BeforeClass
fun classSetup() {
    AdPreloadManager.setDestroyedForTest(false)
    AdPreloadManager.setInterstitialLoadingForTest(false)
    AdPreloadManager.setRewardedLoadingForTest(false)
    AdPreloadManager.onInterstitialReady = null
    AdPreloadManager.onRewardedReady = null
}
```

> **Critical:** the cold-start integration test (`@Ignore`) calls `clearCallbacks()` in its `finally` block, leaving `isDestroyed=true`. If a race-guard test runs in the same process without resetting, `isDestroyed=true` causes the `isDestroyed` guard to absorb the stale call instead of exercising the `isInterstitialLoading.compareAndSet` race path — the test passes for the wrong reason.

### 9.4 Real Ads on Test Lab — NEVER in CI

The workflow has a `real_ads_on_test_lab` input (default `false`). Enabling it:
- Removes test-creative registration from AdMob
- Sends **billable/invalid traffic** on production ad units
- Should only be used for **one-off manual verification**, never automated CI

**Rule:** keep `real_ads_on_test_lab=false` in all automated workflows.

## 10. Standard Release Flow

1. Make code/config changes.
2. Bump the version in both places (§2) — Gradle files + primary workflow defaults.
3. Verify signing secrets are present in GitHub (keystore base64 + passwords).
4. Push to GitHub (the repo's `main`) — that's what CI builds from. Replit checkpoints alone do **not** reach CI.
5. Trigger the workflow (`android-sdk-update-v25.yml`, via `workflow_dispatch`). Confirm the version inputs match what you just bumped.
6. After it goes green, verify the produced AAB:
   - AD_ID present (`unzip -p app-release.aab base/manifest/AndroidManifest.xml | grep -a AD_ID`)
   - both OPTIMIZE meta-data entries present
   - `versionName` in the AAB matches what you intended (`aapt dump badging`)
   - Unity/Vungle adapter classes present (if mediation enabled)
7. Upload to Play, then **supersede old artifacts** in all tracks.
8. Monitor **Play Vitals ANR trend for 7–14 days** before any further SDK/UMP work.

### 10.1 Bridge Contract Deliverable Check

If the release includes any change to ad loading, showing, or callback behavior (guard branches, new telemetry codes, new `window.on*` callbacks), update `WEB_APP_BRIDGE_GUIDE.md` **before** the release. The web app team relies on this document as the source of truth for the JS bridge contract.

## 12. Troubleshooting

| Symptom | Likely Cause | Fix |
|---|---|---|
| `Manifest merger failed` on OPTIMIZE flags | Value is `"1"` instead of `"true"` | Change to `android:value="true"` |
| `incompatible version of Kotlin` | Kotlin 1.9.x trying to read ads SDK 2.2.0 metadata | Bump Kotlin to 2.2.0 |
| `Platform declaration clash: setMicActive(Z)V` | Explicit `fun setMicActive` collides with Kotlin property setter | Rename to `setMicState` |
| Zero Unity fill, no error | Adapter ≠ SDK version (e.g. 4.12.x with SDK 24.9.0) | Use `unity:4.16.6.0` + `unity-ads:4.16.6` |
| Zero Unity fill, no error | Group is **waterfall** (ended Jan 31 2026) | Reconfigure Unity source as **bidding** |
| Adapter not initializing in logcat | Adapter/SDK lines missing from Gradle | Add both lines, re-run CI build |
| Activity leak in LeakCanary | Old ad manager instance still receiving callbacks | Ensure `cleanup()` calls `handler.removeCallbacksAndMessages(null)` and sets `isDestroyed = true` |
| App Open ad never shows | `isMicActive` stuck true after crash | Check mic watchdog + JS heartbeat are wired |
| Ad shows but no impression | `isShowingAd` stuck true after exception | Add try/catch around `ad.show()` with `isShowingAd = false` in catch |
| `ActivityScenario.launch` crash on Test Lab | `TestHostActivity` not exported (API 33+) | Set `android:exported="true"` in androidTest manifest |
| `ActivityScenario.launch` hang on Test Lab | `TestHostActivity` extends plain `Activity` | Change to extend `ComponentActivity` |
| Test passes for wrong reason (cold start) | Stale `isDestroyed=true` from prior test | Add `@BeforeClass` reset of singleton state |
| Rewarded promise hangs | `onRewardEarned` not set before `showRewarded()` | Set callback before calling show |
| Wrong/typo placement, or iOS Game ID used | Mapping uses iOS Game ID | Re-check mapping uses the **Android** Game ID + exact placement |
| Play upload rejected | Reused version code | Bump `versionCode` (all 3 places) |
| `Syntax error: Label must be named` + cascading missing-brace errors | `return@try` used inside a `try` block (`try` is a reserved keyword, not a valid label) | Wrap the body in `run testBody@{ ... }` and use `return@testBody`; keep `try/finally` outside the `run` wrapper |
| `NumberFormatException` in `AdExperimentConfig` on cold start | `toInt(16)` overflows signed Int for hex > 0x7fffffff | Use `toLong(16) and 0xffffffffL` with try/catch fallback |
| Ad stack never initializes; zero impressions in Test Lab | `AdExperimentConfig` crash kills `AdMobBridge` construction before ad managers start | Fix computeVariant parse; add `AdExperimentConfigTest` to CI |

  # Part 2 — Update Playbook

  A practical playbook for updating the BabelWords Android app (a native WebView
wrapper, same architecture as LinguaGT/LinguaVibe). It captures the hard-won
lessons from recent releases so future updates go smoothly the first time.

> **Read this first:** the Android app builds **only in GitHub Actions** — there
> is no local Android SDK/Gradle in this environment. You cannot compile-test a
> change here; the first real signal is the CI build. Plan changes carefully and
> verify the merged manifest and the produced AAB after every build.

## 2. How to bump the app version (every release)

Change the version in **two places** — Gradle files and the primary CI workflow. The CI build overrides Gradle defaults with `-Pandroid.injected.version.code/name`, so workflow inputs/env take precedence. Keep them synchronized or CI will ship a stale/duplicate number.

1. **Gradle files** (the fallbacks when CI inputs are absent):
   - `android/app/build.gradle` → `versionCode` and `versionName`
   - `android/build.gradle` → the `versionCode` / `versionName` in the
     `subprojects { ... defaultConfig { ... } }` block
2. **CI workflow** (`.github/workflows/android-sdk-update-v25.yml`) → three spots:
   - the `version_name` input **description** (e.g. `'Version Name (e.g., 54.0.0)'`)
   - the `version_name` input **default**
   - the `env:` fallbacks `VERSION_CODE` and `VERSION_NAME`

**Precedence rule:** `workflow_dispatch` input → env fallback → Gradle default. If you forget to bump the workflow defaults, the next manual CI run can silently reuse an old version even though Gradle files look correct.

> **Backup workflow files** (`.github/workflows/sed8zU4od`, `.github/workflows/sedNhpMCX`) are stale `sed` in-place edit backups. They are **not** authoritative CI config. If they are ever restored to active use, update them then; do not treat them as a required release checklist item.

**Rules**
- `versionCode` must be a **higher integer** than any artifact ever uploaded to
  Play (across ALL tracks). Play rejects re-used or lower codes.
- A version number, once used in a build, is "burned" — bump again for the next
  attempt even if the previous build failed and produced nothing.
- After editing, verify there are no stragglers:
  ```bash
  rg --color never -n "<OLD_VERSION>" android/ .github/workflows/android-sdk-update-v25.yml
  ```
  (Ignore `127.0.0.1` in `network_security_config.xml` — that's an IP, not a version.)

## 3. AdMob / ANR — the real fixes

### 3a. ANR mitigation (the important one for revenue)
ANRs reported in Play Vitals as `MessageQueue.nativePollOnce` and/or
`AdMobBridge.loadInterstitialAd` ("Input dispatching timed out") are caused by
the Google Mobile Ads SDK doing synchronous work on the **main thread** during
init and ad loading.

**Fix — add these two `<meta-data>` flags inside `<application>`** in
`android/app/src/main/AndroidManifest.xml`:
```xml
<meta-data
    android:name="com.google.android.gms.ads.flag.OPTIMIZE_INITIALIZATION"
    android:value="true"/>
<meta-data
    android:name="com.google.android.gms.ads.flag.OPTIMIZE_AD_LOADING"
    android:value="true"/>
```
These move SDK init + ad loading off the main thread. They work on any recent
ads SDK and require **no web-app / JS-bridge changes** — the
`window.AndroidAdBridge` contract is untouched.

**Also keep the ads SDK reasonably current.** Newer play-services-ads releases
ship additional off-main-thread/ANR fixes, so `flags + current SDK` is the
strongest combination — not just the flags alone.

### 3b. No web-app changes for native ad/ANR work
The JS bridge contract (`loadInterstitial()`, `showInterstitial()`,
`isInterstitialReady()`, and the `window.on*` callbacks) is stable. Native SDK
bumps, OPTIMIZE flags, and version bumps never require touching the web app.

## 4. ⚠️ play-services-ads ↔ Kotlin version coupling (critical)

This is the trap that broke a recent build.

- **play-services-ads 24.x is compiled with Kotlin 2.x.** The 24.9.0 jars carry
  Kotlin **metadata 2.2.0** and transitively pull **kotlin-stdlib 2.1.0**.
- A **Kotlin 1.9.x** compiler can only read metadata up to 2.0.0, so the build
  fails at `:app:compileReleaseKotlin` with:
  ```
  e: ... play-services-ads-24.9.0 ... was compiled with an incompatible
     version of Kotlin. The binary version of its metadata is 2.2.0,
     expected version is 1.9.0.
  ```
  …plus **cascading** errors in your own `.kt` files (e.g. `Unresolved
  reference: mapOf` / `to`) — those are *symptoms* of the compiler failing to
  load stdlib, not real code bugs.

**Rule:** the project's Kotlin version (`org.jetbrains.kotlin.android` plugin
version **and** `ext.kotlin_version` in `android/build.gradle`) must be **>=**
the Kotlin version the ads SDK was built with. We are on **Kotlin 2.2.0** to
match play-services-ads 24.9.0.

**compileSdk ceiling:** stay on the **24.x** ads line while `compileSdk = 35`.
The **25.x** line targets Android 16 / API 36 and can force `compileSdk 36`.

**Check the latest ads version:**
`https://dl.google.com/dl/android/maven2/com/google/android/gms/play-services-ads/maven-metadata.xml`

### Kotlin upgrade risk
Kotlin 2.x uses the stricter **K2** compiler. This project is a *good* candidate
(no Jetpack Compose, no kapt/annotation processing — the two usual pain points),
so risk is low. But K2 can still surface latent strictness issues (nullability,
type inference, smart-cast edge cases) that are **only visible in the CI build**.
If they appear, fix them as small targeted changes — don't revert Kotlin.

## 5. Google Play "AD_ID permission missing" — it's OPERATIONAL, not a bug

When Play warns that AD_ID is missing "in an active artifact":

- The source manifest **does** declare it:
  ```xml
  <uses-permission android:name="com.google.android.gms.permission.AD_ID" />
  ```
  and play-services-ads merges it again. The compiled AAB verifiably contains it.
- The warning persists because Play validates **every active artifact across all
  tracks**. Old AABs built *before* AD_ID existed stay active and trigger it.
  **Rewriting the manifest does nothing.**

**What actually fixes it:**
1. Verify the AAB you're uploading really has it:
   ```bash
   unzip -p app-release.aab base/manifest/AndroidManifest.xml | grep -a AD_ID
   ```
   (The permission string is readable inside the protobuf.)
2. In Play Console, **supersede/deactivate the old releases** in every track
   (Internal / Closed / Open / Production).
3. Complete **App content → Advertising ID** declaration.
4. **NEVER click "Release without permission"** — that zeroes the advertising ID
   and kills ad revenue.

A **CI gate** in the workflow already fails the build if AD_ID is absent from the
compiled merged manifest (it runs `aapt dump permissions` after the AdMob App ID
check). Keep that gate.

## 6. Standard release flow

1. Make code/config changes.
2. Bump the version in both places (§2) — Gradle files + primary workflow defaults.
3. Verify signing secrets are present in GitHub (keystore base64 + passwords).
4. Push to GitHub (the repo's `main`) — that's what CI builds from. Replit
   checkpoints alone do **not** reach CI.
5. Trigger the workflow (`android-sdk-update-v25.yml`, via `workflow_dispatch`).
   Confirm the version inputs match what you just bumped.
6. After it goes green, verify the produced AAB:
   - AD_ID present (§5 step 1)
   - both OPTIMIZE meta-data entries present
   - `versionName` in the AAB matches what you intended (ci: `aapt dump badging`)
7. Upload to Play, then **supersede old artifacts** in all tracks.
8. Monitor **Play Vitals ANR trend for 7–14 days** before any further SDK/UMP work.

## 7. Firebase Test Lab instrumentation gates

The CI workflow runs **instrumentation tests on real cloud devices** as release gates. These are not optional — they hard-fail the build on `push` to `main` if logcat markers are missing or assertions fail.

| Test class | What it protects | CI hard-fail marker |
|---|---|---|
| `AudioFocusLossInstrumentedTest` | OS mic/audio focus revocation fast path (call / other app) | `MicWatchdog: audio focus lost` + `isMicActive reset` |
| `AppOpenAdManagerRotationTest` | Activity destroyed mid-rotation while ad callback in flight → no crash, no reload | `TestRunner: finished: .*AppOpenAdManagerRotationTest` |
| `MicResumeReconciliationTest` | `MIC_RESUME_RECONCILIATION_MS` ceiling ≤ 10 s; stale mic lock cleared within timeout | `TestRunner: finished: .*MicResumeReconciliationTest` |
| `AdPreloadManagerColdStartTest` | Race-guard invariants (no-inflight + interstitial + rewarded) on fresh process | `COLD_START_RACE_GUARD: all 3 invariants` + `NO_INFLIGHT_RACE_GUARD` |
| `AdMobBridgeShowTelemetryTest` | `showRequested` + `showSuppressed` telemetry deterministically emitted by guards | `TestRunner: finished: .*AdMobBridgeShowTelemetryTest` |

> **Note:** The `coldStart_onFreshProcess_firesPreloadAndDeliversReadyCallback()` test is `@Ignore` (requires real AdMob SDK + network; crashes on Test Lab emulators). CI only validates the **deterministic race-guard** subset — not full cold-start fill. Do not over-interpret a green CI as proving real-network preload works.

**Required secrets:** `GCP_SA_KEY` and `GCP_PROJECT_ID` must be present in GitHub Secrets for Test Lab runs. Without them, the build skips instrumentation gates, which is allowed on `workflow_dispatch` but **hard-fails on `push` to `main`**.

### 7.1 AndroidTest host activity invariant

Instrumentation tests that need a real Activity instance use `TestHostActivity`:
- **Must extend `ComponentActivity`** (not plain `Activity`). ActivityScenario from `androidx.test:core` has intermittent launch failures on Firebase Test Lab emulators with plain `Activity` subclasses. `ComponentActivity` provides the androidx lifecycle hooks ActivityScenario needs.
- **Must NOT extend `AppCompatActivity`**. A platform translucent theme (`@android:style/Theme.Translucent.NoTitleBar`) is used in `androidTest/AndroidManifest.xml` to avoid build-time resource resolution errors. AppCompatActivity with a platform theme throws `IllegalStateException` at runtime.
- **Never change the theme** in `androidTest/AndroidManifest.xml` to an AppCompat theme — the CI build does not package AppCompat resources for the androidTest variant.

```kotlin
// android/app/src/androidTest/java/com/lingualink/linguagt/ads/TestHostActivity.kt
class TestHostActivity : ComponentActivity()
```

**Failure symptom if regressed:** `ActivityScenario.launch(TestHostActivity::class.java)` hangs or crashes with `androidx.test.core.app.InstrumentationActivityInvoker$EmptyActivity` launch failure on Test Lab.

### 7.2 Cold-start testing — two-stage CI approach

You cannot simulate cold start (process death) inside a single instrumentation test because the test runner and target app share the **same process** (`com.lingualink.linguagt`). Calling `am force-stop` from within the test kills the instrumentation runner along with the app, so the assertion never runs.

**The CI workaround:** Two separate `gcloud firebase test android run` invocations:
1. **Robo test** — exercises the app, then Test Lab kills the process
2. **Instrumentation test** — runs on a **fresh device** with JVM singleton fields at defaults

This boundary achieves genuine OS-level process death without the same-process limitation. The cold-start test asserts `isDestroyed==false` (JVM default) at entry, confirming the fresh-process guarantee.

### 7.3 Same-process test isolation — `@BeforeClass` reset

When Test Lab runs multiple test classes, they may execute in the **same process**. AdPreloadManager is a JVM singleton; stale state from a prior test can silently corrupt assertions.

**Pattern:** `@BeforeClass` + `@Before` methods reset singleton state:
```kotlin
@BeforeClass
fun classSetup() {
    AdPreloadManager.setDestroyedForTest(false)
    AdPreloadManager.setInterstitialLoadingForTest(false)
    AdPreloadManager.setRewardedLoadingForTest(false)
    AdPreloadManager.onInterstitialReady = null
    AdPreloadManager.onRewardedReady = null
}
```

> **Critical:** the cold-start integration test (`@Ignore`) calls `clearCallbacks()` in its `finally` block, leaving `isDestroyed=true`. If a race-guard test runs in the same process without resetting, `isDestroyed=true` causes the `isDestroyed` guard to absorb the stale call instead of exercising the `isInterstitialLoading.compareAndSet` race path — the test passes for the wrong reason.

### 7.4 In-process bridge telemetry testing — no network

`AdMobBridgeShowTelemetryTest` verifies telemetry without real AdMob SDK or network:
- **Test-mode constructor:** `AdMobBridge(skipSdkInit=true)` bypasses `MobileAds.initialize()` and real ad loading
- **CapturingWebView:** A `WebView` subclass that records every `evaluateJavascript()` call into a `mutableList<String>`. Tests assert on captured JSON payloads — pure in-process, deterministic, zero flakiness
- **No Test Lab device needed** — runs in any instrumentation process, but CI also runs it on Test Lab for cross-device validation

### 7.5 Test Lab reliability settings

CI uses `--num-flaky-test-attempts 2` for the cold-start suite and show-telemetry tests. This retries the entire test class on transient emulator provisioning failures (e.g., `InstrumentationResultParser` crash, device disconnect). The retry is at the **gcloud** level, not JUnit level — individual test methods still fail hard.

### 7.6 Real ads on Test Lab — NEVER in CI

The workflow has a `real_ads_on_test_lab` input (default `false`). Enabling it:
- Removes test-creative registration from AdMob
- Sends **billable/invalid traffic** on production ad units
- Should only be used for **one-off manual verification**, never automated CI

**Rule:** keep `real_ads_on_test_lab=false` in all automated workflows. The deterministic tests (`CapturingWebView`, `skipSdkInit`) validate telemetry and guards without touching real ad traffic.

## 8. Gotchas / red herrings

- **ripgrep ANSI color glitch:** captured `rg` output can make a manifest line
  like `...AD_ID"` *look* mangled (e.g. `.n`). It's purely a terminal color-code
  display artifact — the file bytes are fine. Verify with `od -c` or `grep -c`,
  not colored `rg` output.
- **A failed build still "uses up" a version number** — bump again next attempt.
- **Primary workflow:** the only active CI build file is
  `.github/workflows/android-sdk-update-v25.yml`. Other files in `.github/workflows/`
  (`compile-check.yml`, stale `sed*` backups, any `archive/` directory) are not
  part of the release build — do not edit them for version bumps.
- **Compile check disabled:** The standalone `compile-check.yml` and the internal
  "Quick Compile Check" step were both removed. The build goes straight to
  `bundleRelease`; Gradle catches real errors during the actual build.
- **AdMob IDs** (reference): App ID `ca-app-pub-9991891515643313~7514450861`;
  Interstitial `/5076005693`; Rewarded `/6313049833`. Only Interstitial and
  Rewarded are enabled (Banner disabled by policy).
- **`AdExperimentConfig` crash trap:** `computeVariant` must use unsigned Long
  parse (`toLong(16) and 0xffffffffL`) — signed `toInt(16)` crashes on hex
  prefixes above `0x7fffffff` (e.g., `97d62620`), killing the entire ad stack.

## Pre-Release Verification Checklist

Before releasing a new version, verify every item:

- [ ] AdMob SDK initializes successfully (logcat shows "AdMob SDK initialized").
- [ ] Ad unit IDs are correct and match in all files.
- [ ] AndroidManifest has the AdMob App ID and `AdActivity`.
- [ ] `OPTIMIZE_INITIALIZATION` and `OPTIMIZE_AD_LOADING` manifest flags are present.
- [ ] `AD_ID` permission is declared.
- [ ] Native ad preloading is active (logcat shows "Interstitial ready" and "Rewarded ready").
- [ ] Audio routing toggles correctly (logcat shows MODE_NORMAL and mode restored).
- [ ] UMP consent flow is wired and callbacks propagate to both bridges.
- [ ] `AndroidAdBridge` is registered as the JS interface.
- [ ] Activity resumed flag is synced (logcat shows "Activity resumed state: true").
- [ ] Foreground tracking is active (logcat shows foreground/background events).
- [ ] Ad expiration checks are present.
- [ ] Concurrent show guard (`isShowingAd`) is active with a watchdog.
- [ ] All failure paths emit callbacks (no hung Promises).
- [ ] Ad impression counters are logged (logcat shows "INTERSTITIAL IMPRESSION").
- [ ] Subscription gating is wired.
- [ ] Version is bumped in all three files.
- [ ] Test Lab safety is active (logcat shows test-device registration).
- [ ] Build is CI-only (no local debug signing).
- [ ] **v55.1+:** Frequency cap consumed in `onAdShowedFullScreenContent`, not in `show()` guard.
- [ ] **v55.1+:** Non-retryable errors skip retry; only `ad_stale_reloading` and `no_cached_ad` auto-retry.
- [ ] **v55.1+:** 45s global impression cooldown across all formats.
- [ ] **v55.1+:** `AdExperimentConfig.computeVariant()` uses unsigned Long parse (`toLong(16) and 0xffffffffL`) with try/catch.
- [ ] **v56+:** `AdExperimentConfigTest` passes in CI Firebase Test Lab.
- [ ] **v56+:** Compile-check jobs removed from main CI workflow.

## On-Device Verification Steps

After installing a CI-built APK:

1. **Open the app** — check logcat for "AdMob SDK initialized" and "Interstitial ready".
2. **Tap the interstitial button** — ad should show with full volume. Logcat shows "MODE_NORMAL".
3. **Dismiss the ad** — logcat shows "Ad dismissed" and "AudioManager mode restored".
4. **Tap the rewarded button** — ad should show. Logcat shows "REWARDED IMPRESSION".
5. **Earn the reward** — logcat shows "Reward earned" and the web app grants the reward.
6. **Background the app mid-ad** — app returns to background. Logcat shows "App entered background".
7. **Foreground the app** — ad resumes or closes. Logcat shows "App entered foreground".

If all seven steps pass, the Android app is fully configured for maximum impressions.
